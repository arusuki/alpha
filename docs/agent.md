# Agent API

管理员在“Agent 设置 → API Key 与模型”配置 Chat Completions 或 Responses 连接，然后在“空间用量 → 生成空间报告”一键发起分析。报告绑定当前查看的扫描记录（包括历史记录），复用已有目录统计，按需补查大目录。生成时校验记录版本，冲突要求刷新后重试，不自动换到最新记录。追问读取同一记录的最新已提交版本。

报告窗口默认展示诊断对话，模型回复以气泡实时呈现，各组结果可折叠查看，支持停止分析、历史会话、继续追问和 Markdown 导出；“完整报告”视图集中阅读已完成的回复，关闭窗口不停止后台分析。未配置模型时给出设置入口。仅创建者可读取分析会话；已删除源扫描的报告仍可查看与导出，继续分析需选择新的扫描记录重新生成。

## 报告设计

报告的任务定义由服务端维护，浏览器提交所选记录 ID、版本和最大并行 Agent 数。

1. **每 4 个容器一组**：分页读取所选记录的全部容器，按独占实际占用降序固定分组；最后一组可以不足 4 个。无容器时直接说明，不调用模型。开始探索后不重新排序，避免漏掉或重复容器。
2. **每组自主探索**：按页面指定的最大并行数执行（1–16，默认 3）。初始启动不超过上限的组，任一组结束立即补充下一组，不等待同批其他组。每组创建全新的模型上下文、工具状态和模型会话标识，不复用刚结束的 Agent 对话。Agent 自行查询可写层、挂载及具体文件用途，可跨容器核对共享关系。不限制工具轮次、目录探索次数或结果条目数，不强制提前总结；除大资产外也排查缓存、临时数据和开发工具积累，混合目录拆开判断。
3. **固定四类**：① 可立即删除；② 存在争议（给出具体条件或取舍）；③ 必须保留；④ 放错位置（说明迁移依据和落点）。根据目录结构和软件用途判断可丢弃缓存，避免把所有缓存笼统列为争议；模型资产、运行中临时数据和编辑器历史仍需分别说明影响，不能凭目录名一概判为垃圾。
4. **简洁结果**：每组输出经过校验的 JSON，包含各容器的具体目录/文件、物理与容器内路径、实际占用、分类、用途和处理条件。没有条目时说明原因；不设置条目数或说明字数上限。格式无效或遗漏容器时，将具体校验错误反馈给模型，在原上下文中修正，保留已查询证据；发布前还会批量读取同一版本的记录，核对物理路径、容器映射和实际分配字节数；拼错路径、归属混淆或占用不符同样反馈修正，无法核实的项目移入备注。只有校验通过才发布结果。单组存储或模型请求失败时结束该组并释放名额，其余组继续执行；不自动重试失败的模型请求。全部组结束后，有失败则会话标为失败，不生成覆盖不全的总报告，已完成组的结果仍可查看。点击停止取消所有运行组，不再启动等待组。
5. **归并报告**：程序将各组结果按四类、固定文件用途归并，同用途按占用降序，只生成一份 Markdown 表格报告，不再调用模型扩写。数据集、模型权重、实验产物、环境、包缓存、编译缓存、日志、临时文件和编辑器历史分别聚合。相同物理路径只列一次，保留引用它的各容器；组间分类冲突转为“存在争议”。共享路径采用最后一次校验观察到的占用，不按组号推断新旧。每类显示已知实际占用总计，同类父子路径仅计入已知占用的上级目录；容量未知且未被已知上级覆盖的条目标明数量，不当作零占用。不同类别可能存在父子重叠，四类总计不可直接相加，也不代表可回收空间。

报告覆盖容器空间用途及有实际清理价值的项目；记录信息在末尾集中标注。工具只读元数据，不执行清理，不验证进程依赖或内容重复。第四类表示存放位置需要调整，不表示可以删除。

## 诊断清理 workflow

管理员在“存储 → 诊断清理”选择自己生成的完整报告，点击“提取报告条目”。服务端把完整 Markdown 报告和原始物理路径清单交给独立 Agent，路径清单用于还原表格排版转义，不截断、不带入后续追问，也不开放任何工具。Agent 返回包含物理路径、原分类和简要说明的 JSON；服务端按报告发布时保存的已验证条目清单核对全部四类的覆盖、唯一性及分类，不允许遗漏、添加或替换路径。格式或覆盖不符时在原上下文修正，最多三次；模型请求失败直接结束，页面可重新发起提取。

提取页复用分析会话的 SSE 事件，滚动展示模型 JSON 输出、校验失败原因和模型公开返回的思考内容；阅读位置靠近底部时跟随新内容，向上阅读时保持位置。页面每项只保留最近 32000 个字符，并提示较早内容已截断；服务端每项过程快照保留最近 32 KiB，替换旧快照，重新进入仍可回看最近片段。思考内容默认折叠，展开状态在增量更新时保留。Chat Completions 可展示模型返回的思考字段；Responses 需在 Agent 设置中启用公开思考摘要，具体内容取决于模型支持。模型回复本身不按展示窗口截断，完整 JSON 仍用于全部路径校验；提取请求的 SSE 总量上限为 64 MiB，其他分析请求保持 8 MiB。停止或离开页面后最近过程片段保留，SSE 中断时从消息游标续读。

前端解析已验证结果，展示路径、容器位置、占用、简要说明和原报告依据，支持分类筛选、搜索和勾选。所有条目默认不选中。每份报告复用同一提取结果，刷新和重新登录保留处理状态；源扫描被删除时仍可提取、查看报告，但不能删除实际内容。已结束的提取任务可在确认后删除，其过程消息、提取条目与处理状态一并移除；原始完整报告及实际磁盘内容不受影响，报告可重新提取。运行中的提取或删除任务不能删除。

点击“删除所选”会列出确切物理路径、分类及说明，输入服务账号的 sudo 密码并确认后才提交已保存条目的 ID，每批最多 100 项；父子目录不可同时提交。删除在后台执行，逐项保存成功、失败或待核对状态，离开页面后继续，支持停止；停止可能保留部分已删除内容。删除不由 Agent 执行，模型工具始终只读。操作要求报告创建者的管理员权限及 CSRF，并记录所选路径的审计事件。

实际清理由服务账号通过 sudo 启动一次性宿主机辅助程序执行，使用目录描述符与 `openat2` 防止符号链接跳转和跨挂载递归；不通过 Docker 辅助容器提权。系统路径、平台数据及其祖先、排除路径、挂载点及包含挂载点的目录、Docker 数据根及可写层根不可删除。sudo 认证失败、路径已变化或系统不支持该操作会逐项报错；只有已记录的物理目录或文件可操作。它与扫描共用存储互斥锁，失败不会清空列表或报告。服务重启时，未确认结果的删除标记为待核对，不自动再次删除。扫描和报告保留历史状态，清理后重新扫描才能更新用量。

Docker 可写层条目保留报告中的物理路径作为确认范围与结果标识，实际删除映射到当前 OverlayFS 合并视图中的容器路径。辅助程序根据本批扫描记录中的可写层根和当前 `/proc/self/mountinfo` 的 `upperdir` 建立映射，打开并固定合并挂载的目录描述符，以 `statx` 挂载 ID 和文件系统类型核验身份，再在该描述符内禁止符号链接跳转和跨挂载访问。不会直接递归删除 `diff`，也不会通过字符串替换猜测 `merged` 路径。未挂载（例如容器已停止）、只读、映射不唯一、身份变化或涉及受保护挂载时，本批在删除前失败；不会自动启动容器或退回底层物理删除。容器卷、绑定挂载及其子路径与祖先也按扫描记录保护，即使它们只出现在容器的挂载命名空间中。

合并视图会隐藏 whiteout 删除标记，因此缓存中的 `0:0` 字符设备不会被当成待删除的文件。清理会删除所选容器路径及其中全部可见内容；镜像原有内容只在该容器中被隐藏，镜像本身不变。内核负责保留或创建删除标记，重试一个已从合并视图消失的目标按已删除处理，不移除其底层标记。删除成功表示该容器路径已移除，不表示 `diff` 中一定没有对应元数据，也不保证释放与历史报告完全相同的字节数。

清理目录时，普通文件、符号链接、Unix socket 和 FIFO 只移除目录项，不跟随链接，也不打开或连接特殊文件；字符设备、块设备及未知类型仍会中止删除。删除失败会保存并显示具体操作、失败子路径及系统原因，保留可能已部分删除的提示。扫描完成不代表目录被锁定，容器或其他进程仍可能修改内容；一次失败不能仅凭旧提示判断为扫描过期。

每批只启动一次 `/usr/bin/sudo -S -k`，忽略且不更新 sudo 的凭据缓存。密码只在当前请求与后台任务内存中短暂持有；识别到 sudo 密码提示后通过匿名 stdin 管道发送一次，随后清空可变字节缓冲区。辅助程序就绪后才发送本批路径，它不会接收密码。密码不进入命令行参数、环境变量、数据库、审计、模型上下文、临时文件、浏览器存储或错误结果；sudo/PAM 的原始 stderr 直接丢弃，使用固定认证错误提示，避免回显泄漏。认证失败不自动重发，下次提交必须重新输入。窗口在提交、关闭及退出登录时清空密码，禁用自动填充。

服务账号需具备执行当前程序 `cleanup-helper` 的 sudo 权限。部署模板仍保留 `NoNewPrivileges=true`：普通账号在此限制下无法通过 sudo 提权，是否调整该部署设置需另行确认；提权子程序只接收本批确认范围，并再次检查受保护路径与当前挂载点。认证最多等待 30 秒。取消或服务退出会关闭控制管道，辅助程序检测 EOF 后停止，防止 root 删除进程脱离本次任务继续运行。页面密码是宿主机服务账号密码，不是平台登录密码。

## HTTP 接口

所有接口要求管理员会话。变更请求携带 `X-CSRF-Token`，有请求体时使用 JSON，令牌从 `GET /api/session` 获取；分析会话仅创建者可访问。

| 接口 | 请求与结果 |
|---|---|
| `GET /api/agent/settings` | 配置及版本，Key 仅返回 `has_api_key` |
| `PUT /api/agent/settings` | `{revision, value}`；value 包含 `protocol`、`endpoint`、`model`、`api_key`、`clear_api_key`、`timeout_seconds`、`reasoning_summary` |
| `GET /api/agent/sessions` | 当前账号最近 50 个分析 |
| `GET /api/agent/cleanup-reports` | 自己的全部完整报告及对应提取任务 |
| `POST /api/agent/cleanups` | `{report_id}`；读取完整报告、提取全部条目，返回 202；失败或停止的提取可重试，完成结果复用 |
| `GET /api/agent/cleanups/:id` | 会话状态、阶段 `phase`（extract/delete）、条目 JSON 及逐项删除状态 |
| `DELETE /api/agent/cleanups/:id` | 删除本人已结束的提取任务及其过程、条目和处理状态；保留原始报告与磁盘内容，运行中返回 409 |
| `POST /api/agent/cleanups/:id/delete` | `{entry_ids:[...], sudo_password:"本次 sudo 密码"}`；用户确认后提交 1–100 个条目 ID，返回 202，后台删除；不接受客户端提供的路径 |
| `POST /api/agent/reports` | `{snapshot_id, revision, concurrency}`；concurrency 为 1–16 的整数；从所选已完成扫描生成总报告，返回 202；版本不匹配返回 409 |
| `POST /api/agent/sessions` | `{message}`；新建分析，返回 202 |
| `GET /api/agent/sessions/:id?after=0` | 状态、扫描进度及消息；最多 200 条，返回 `next_after`、`has_more` |
| `GET /api/agent/sessions/:id/events?after=0` | SSE 实时事件；`session` 事件携带与查询接口相同的结构，支持 `Last-Event-ID` 续传 |
| `POST /api/agent/sessions/:id/messages` | `{message}`；继续提问 |
| `POST /api/agent/sessions/:id/retry` | `{requests:[{group_id, request_id}, ...]}`；批量恢复失败 Agent，各自重发最近一次失败的模型请求，按原报告并行上限执行，返回 202；过期请求、已完成分组或已有分析运行时返回 409；整批校验通过后才入队 |
| `POST /api/agent/sessions/:id/cancel` | `{}`；停止模型请求及本轮扫描 |

模型接口必须支持 SSE 流式输出。Chat Completions 使用 `stream:true` 和 `stream_options.include_usage:true`；Responses 使用 `stream:true`、`store:false`。非流式 JSON、缺少结束事件、输出截断和无效工具调用均明确报错，不将部分输出保存为完整报告，不自动重新发起付费请求。协议参考 [Responses 流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events) 与 [Chat Completions 流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。

`reasoning_summary` 是可选布尔设置，默认关闭；开启后仅在 Responses 请求中传递 `reasoning:{summary:"auto"}`，需要所选模型支持。Responses 显示接口返回的思考摘要，不展示原始 reasoning 正文或加密内容。Completions 显示接口通过 `reasoning_content` 或 `reasoning` 文本字段返回的完整思考，不受摘要开关影响；服务未返回思考时不显示该区域。服务不支持摘要参数时报错，需在模型设置中关闭；不自动重试。

`protocol` 为 `completions` 或 `responses`，`endpoint` 支持基础地址或完整接口地址。保存空 Key 表示保留，`clear_api_key:true` 表示清除。

模型请求以 `project-alpha/0.1` 标识客户端，并携带 `x-opencode-session`，分组 Agent 的值为 `分析会话 ID-group-组号`，同组工具轮次保持相同值，各组互不复用；整体追问使用分析会话 ID，新分析使用新 ID。使用 OpenCode Go 或转发它的代理时，需保留该请求头，否则服务会返回 HTTP 400 `MissingSessionID`。接口协议须与所选模型匹配，参见 [OpenCode Go 接口说明](https://opencode.ai/docs/go/#endpoints)。

`POST /api/agent/sessions` 是另行建立全盘基线的自定义分析入口：先扫描宿主机 `/`，启用 Docker 自动发现时也扫描 Docker 资源。Web 一键报告使用 `/api/agent/reports`，不会为每份报告另建全盘扫描。两个入口共用会话、追问、取消与查询接口。

## 对话、上下文与用量

空间用量入口和诊断窗口都可设置“最大并行 Agent 数”，仅用于新诊断；运行中锁定本次上限。侧边栏显示并行上限、运行中和完成数量。诊断窗口左侧按分组列出 Agent，每项显示负责的容器及等待、分析中、完成、失败或停止状态。选择 Agent 后，右侧只展示该组的模型回复、工具状态和分组结果；切换保留思考摘要展开状态与滚动位置。默认跟随一个正在执行的 Agent，它结束后切到另一运行组；其他组启动不会打断当前组的阅读。手动选择后不再自动切换，可用“跟随当前 Agent”恢复。手机上列表改为顶部横向切换。总览与追问、完整报告有独立入口；追问属于整体会话，不会重启或发送到已完成的分组。

诊断对话按时间展示用户问题、模型回复、分组结果和工具状态。用户气泡居右，Agent 回复居左，模型文字流式更新；最终回复直接出现在对话中，与已经流式展示的同一条回复去重。Responses 的“思考摘要”和 Completions 的“完整思考”均流式显示、默认折叠，可按需展开，展开状态不受流式更新影响；历史会话可回看，停止后保留已收到的内容。

点击“重试失败 Agent（数量）”可一次恢复记录中所有具备失败请求上下文的 Agent，按原诊断保存的并行上限运行；其余失败 Agent 排队，任一运行组结束后立即补位。每组只恢复各自最近一次失败请求的已保存上下文和轮次，失败时收到的部分回复不作为输入，先前已执行的查询和目录扫描不重复执行，已完成分组不重跑。重试期间禁用重复提交；单组再次失败不会阻塞其余队列，也不会自动反复重试该请求。全部分组完成后自动合并总报告；仍失败的 Agent 可再次批量重试。停止后未开始的重试保留原失败状态。此操作支持重新打开历史记录及服务重启后恢复，无需新建会话或重新扫描全盘。扫描记录已删除、上下文缺失或接口协议已改变时明确报错；重试使用当前模型连接配置，协议须与原请求一致。Responses 的加密推理不落盘，恢复时使用保存的公开消息和工具结果。

工具以紧凑状态行展示操作名称、目标目录或容器、执行状态和耗时；失败时显示可读错误。准备调用时仅提示操作名称，不显示尚未完成的参数。页面不再展示完整工具 JSON、预载证据、上下文快照、工具定义或 token 统计卡片。分组模型输出的 JSON（包括流式片段）不作为聊天文字展示，仅在校验通过后显示可读的分组结果。校验修正过程显示简短提示。

对话区域独立滚动，靠近末尾时跟随新内容，向上阅读时保持位置，也可“跳到最新”。停止、失败或中断后保留已经收到的文字并标明未完成。关闭窗口不停止后台任务，重新打开后继续恢复对话。

服务端仍保存每次请求的上下文快照和接口返回的 token 用量，供事件记录使用。追问重取当前扫描概览，只带入最近 24 条用户/助手消息；同组工具结果逐次加入后续请求，组间不携带历史工具输出或其他组的分析。内部推理状态只在内存传递，不保存或展示。

通常分析的公开分片约每 150 ms 合并保存为追加事件；清理提取则保存可替换的最新过程快照。浏览器通过 SSE 每约 250 ms 获取已保存消息和扫描进度。连接最多持续 25 秒，随后按消息游标恢复；关闭窗口、刷新页面和重连都不会重复事件或停止后台分析。查询每页最多 200 条，内容约 1 MiB（单个事件完整返回），需要遵循 `has_more` 分页。

分组计划以 `report_plan` 事件持久化，包含本次 `concurrency` 上限和每组的稳定 ID、序号、容器名单；`group_state` 标记组的开始和结束。模型与工具事件显式携带 `group_id`，分组状态文字 `group_status` 和分组结果 `group_report` 使用 `{group_id, text}`，不依赖事件相邻关系。并行事件交错、分页及 SSE 重连均按明确 ID 恢复归属；工具调用以组 ID 与 `call_id` 联合关联。最终报告和后续追问在分组之外。

持久化事件与清理工作流格式对应数据库版本 11；不迁移旧事件、不推断旧分组。旧数据目录会被版本校验拒绝，需使用新的数据目录；不删除或覆盖已有数据。

消息角色包括 `report_plan`、`group_state`、`group_status`、`user`、`status`、预载 `tool_result`、`model_request`、`model_delta`、`model_response`、清理提取校验 `cleanup_validation`、`tool_start`、`tool_end`、`note`、分组结果 `group_report` 和最终 `assistant`。模型事件通过 `request_id` 关联，工具执行通过 `call_id` 关联；分片与最终回复使用不同角色，追问只读取完成的用户/助手消息。失败、停止或重启后，已经保存的公开内容仍可回看，并标明未完成。

## 模型工具

| 工具 | 参数 | 用途 |
|---|---|---|
| `get_overview` | `{}` | 摘要、主机名、已扫描根目录、Docker 发现状态、设备对账及完整性 |
| `list_containers` | `query, sort_by, offset, limit` | 容器排行；支持 `exclusive`、`writable`、`docker_logical` 排序 |
| `list_owners` | `offset, limit` | 用户去重用量与跨用户共享 |
| `get_container` | `container` | 按完整 ID 或精确名称查询存储来源 |
| `get_directory` | `path, offset, limit` | 查询已保存的目录明细 |
| `scan_directory` | `path, depth` | 在原记录上增量探索；执行端读取最新版本，depth 为 1–32 层 |

分组只限定最终结果负责的容器，不屏蔽工具；可查询其他容器、完整概览及用户排行来核对关联。

分页最多 50 项。探索路径须为当前记录中已有的物理目录绝对路径，未知路径需要从已记录的父目录逐层探索；排除平台数据、虚拟文件系统及 Docker merged 视图。增量探索复用基线的后端和排除设置，使用当前保存的扫描模式；与 Web 的目录探索共用 worker、锁、版本校验和发布流程。结果直接更新原记录，Web 的快照、轮询和 SSE 可读取同一版本。所有查询结果携带 `revision` 和 `updated_at`。各 Agent 的模型请求和只读查询可并行；目录扫描和发布前的证据校验共用可取消的串行队列。扫描取得名额后才读取最新版本并提交探索，避免自身发布导致后续调用版本过期；一个 Agent 等待扫描时，其他 Agent 仍可调用模型。存储层仍校验版本；外部并发更新造成的冲突仍明确返回，不绕过校验。

## 执行与数据

同一服务同时运行一个分析会话，会话内按指定上限并行运行分组 Agent；目录扫描共用单 worker。单次分析最长 2 小时，单次目录细查最多 10 分钟；工具调用没有次数预算，模型自主结束分析或由用户停止。服务关闭会取消分析，异常重启后标为中断；已保存的消息和结果保留。

目录细查返回最大 40 个文件、扩展名汇总及 90/180 天 mtime 分布，只读取元数据。mtime 和 ctime 不能证明文件最近被读取或可以删除；文件统计以 `analysis_observed_at` 标记观察时间；每次探索使相交目录的旧文件统计失效，完成后保存本次统计。全盘与局部观察不能相加。统计定义见 [存储统计口径](accounting.md)。

模型服务会收到问题、路径和统计结果。API Key 保存在权限为 `0600` 的 SQLite 文件中，不额外加密，完整备份包含凭据。Key 不回传浏览器、不写入审计或扫描快照；历史消息保存 Responses 的思考摘要及 Completions 接口返回的完整思考，不保存 Responses 原始 reasoning items、内部推理正文或加密推理内容；Responses 的加密推理项只在同一轮分析的内存中回传。
