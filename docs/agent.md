# Agent API

管理员在“设置 → API Key 与模型”配置 Chat Completions 或 Responses 连接，然后在“空间用量 → 生成空间报告”一键发起分析。报告绑定当前查看的扫描记录（包括历史记录），复用已有目录统计，按需补查大目录。生成时校验记录版本，冲突要求刷新后重试，不自动换到最新记录。追问读取同一记录的最新已提交版本。

报告窗口支持后台进度、停止分析、历史会话、统计证据、继续追问和 Markdown 导出；关闭窗口不停止后台分析。未配置模型时给出设置入口。仅创建者可读取分析会话；已删除源扫描的报告仍可查看与导出，继续分析需选择新的扫描记录重新生成。

## 报告设计

报告的任务定义由服务端维护，浏览器只提交所选记录 ID 和版本。设计参考了 Docker 占用排查需求：先找重点容器，再分别解释 bind mount 与可写层，继续整理数据集、模型、缓存和历史日志。旧对话仅用于确定需求，不作为报告数据或模型上下文。

1. **整体对账**：读取文件系统容量、已用/可用、实际已扫描空间、容器独占/共享和未关联容器空间，交代未解释空间与覆盖限制。扫描根目录未覆盖全盘时明确说明。
2. **定位大头**：结合独占排行、可写层排行和用户归属选择排查对象。服务端主动提供可写层前 20 名；Agent 可分页读取其余项。
3. **解释落点**：读取容器的可写层、挂载与日志源，列出宿主机物理路径到容器内绝对路径的映射，解释共享和嵌套挂载。只读镜像层、Docker 逻辑大小、可写层与挂载采用各自口径。
4. **细查与分类**：在每轮最多 6 次探索的预算内优先解释大头；区分数据集、模型、实验产物、软件环境、缓存、日志、编辑器历史与未知内容。文件名和扩展名只支持候选判断；缓存目录中的模型和数据集仍视为数据资产。
5. **时间分布**：需要时补查文件元数据，按 mtime 的 90/180 天分桶，各组内部按实际占用降序；无日期的项单列。不能把 mtime/ctime 当作创建、下载或最近读取时间，不能把最大 40 个文件样本当作全部数据集。
6. **形成报告**：重新读取最新概览后总结，记录源 ID、版本和观察时间。清理候选列出负责人、精确路径、占用、证据、影响和待核实条件；候选占用不等于已确认可回收空间。

最终报告包含“总览与主要结论、重点容器与用户排行、挂载/可写层/宿主机占用、大数据资产与时间分布、清理候选与长期治理、覆盖范围/证据/待确认事项”。工具仅读取文件元数据，不能验证进程使用、内容重复或安全删除。报告不执行清理；未覆盖的容器或目录列入后续排查。

## HTTP 接口

所有接口要求管理员会话。变更请求携带 `X-CSRF-Token` 和 JSON 请求体，令牌从 `GET /api/session` 获取；分析会话仅创建者可访问。

| 接口 | 请求与结果 |
|---|---|
| `GET /api/agent/settings` | 配置及版本，Key 仅返回 `has_api_key` |
| `PUT /api/agent/settings` | `{revision, value}`；value 包含 `protocol`、`endpoint`、`model`、`api_key`、`clear_api_key`、`max_rounds`、`timeout_seconds` |
| `GET /api/agent/sessions` | 当前账号最近 50 个分析 |
| `POST /api/agent/reports` | `{snapshot_id, revision}`；从所选已完成扫描生成总报告，返回 202；版本不匹配返回 409 |
| `POST /api/agent/sessions` | `{message}`；新建分析，返回 202 |
| `GET /api/agent/sessions/:id?after=0` | 状态、扫描进度及消息；最多 200 条，返回 `next_after`、`has_more` |
| `POST /api/agent/sessions/:id/messages` | `{message}`；继续提问 |
| `POST /api/agent/sessions/:id/cancel` | `{}`；停止模型请求及本轮扫描 |

`protocol` 为 `completions` 或 `responses`，`endpoint` 支持基础地址或完整接口地址。保存空 Key 表示保留，`clear_api_key:true` 表示清除。

`POST /api/agent/sessions` 是另行建立全盘基线的自定义分析入口：先扫描宿主机 `/`，启用 Docker 自动发现时也扫描 Docker 资源。Web 一键报告使用 `/api/agent/reports`，不会为每份报告另建全盘扫描。两个入口共用会话、追问、取消与查询接口。

## 模型工具

| 工具 | 参数 | 用途 |
|---|---|---|
| `get_overview` | `{}` | 摘要、主机名、已扫描根目录、Docker 发现状态、设备对账及完整性 |
| `list_containers` | `query, sort_by, offset, limit` | 容器排行；支持 `exclusive`、`writable`、`docker_logical` 排序 |
| `list_owners` | `offset, limit` | 用户去重用量与跨用户共享 |
| `get_container` | `container` | 按完整 ID 或精确名称查询存储来源 |
| `get_directory` | `path, offset, limit` | 查询已保存的目录明细 |
| `scan_directory` | `path, revision, depth` | 在原记录上增量探索；版本必须匹配，depth 为 1–3 层 |

分页最多 50 项。探索路径须为当前记录中已有的物理目录绝对路径，未知路径需要从已记录的父目录逐层探索；排除平台数据、虚拟文件系统及 Docker merged 视图。增量探索复用基线的后端和排除设置，使用当前保存的扫描模式；与 Web 的目录探索共用 worker、锁、版本校验和发布流程。结果直接更新原记录，Web 的快照、轮询和 SSE 可读取同一版本。所有查询结果携带 `revision` 和 `updated_at`；遇到版本冲突时重新查询，再决定是否继续探索。

## 执行与数据

同一服务同时运行一个分析，扫描共用单 worker。单次分析最长 2 小时，单次目录细查最多 10 分钟，每轮最多发起 6 次目录探索。服务关闭会取消分析，异常重启后标为中断；已保存的消息和结果保留。

目录细查返回最大 40 个文件、扩展名汇总及 90/180 天 mtime 分布，只读取元数据。mtime 和 ctime 不能证明文件最近被读取或可以删除；文件统计以 `analysis_observed_at` 标记观察时间；每次探索使相交目录的旧文件统计失效，完成后保存本次统计。全盘与局部观察不能相加。统计定义见 [存储统计口径](accounting.md)。

模型服务会收到问题、路径和统计结果。API Key 保存在权限为 `0600` 的 SQLite 文件中，不额外加密，完整备份包含凭据。Key 不回传浏览器、不写入审计或扫描快照；历史消息不保存原始 reasoning items。
