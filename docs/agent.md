# Agent API

管理员在“Agent 设置 → API Key 与模型”配置 Chat Completions 或 Responses 连接，然后在“空间用量 → 生成空间报告”一键发起分析。报告绑定当前查看的扫描记录（包括历史记录），复用已有目录统计，按需补查大目录。生成时校验记录版本，冲突要求刷新后重试，不自动换到最新记录。追问读取同一记录的最新已提交版本。

报告窗口默认展示完整对话过程，各组结果可折叠查看，支持实时进度、停止分析、历史会话、统计证据、继续追问和 Markdown 导出；“完整报告”视图集中阅读已完成的回复，关闭窗口不停止后台分析。未配置模型时给出设置入口。仅创建者可读取分析会话；已删除源扫描的报告仍可查看与导出，继续分析需选择新的扫描记录重新生成。

## 报告设计

报告的任务定义由服务端维护，浏览器只提交所选记录 ID 和版本。

1. **每 4 个容器一组**：分页读取所选记录的全部容器，按独占实际占用降序固定分组；最后一组可以不足 4 个。无容器时直接说明，不调用模型。开始探索后不重新排序，避免漏掉或重复容器。
2. **每组自主探索**：组间顺序执行，每组使用全新的模型上下文。Agent 自行查询可写层、挂载及具体文件用途，可跨容器核对共享关系。不限制工具轮次、目录探索次数或结果条目数，不强制提前总结；除大资产外也排查缓存、临时数据和开发工具积累，混合目录拆开判断。
3. **固定四类**：① 可立即删除；② 存在争议（给出具体条件或取舍）；③ 必须保留；④ 放错位置（说明迁移依据和落点）。根据目录结构和软件用途判断可丢弃缓存，避免把所有缓存笼统列为争议；模型资产、运行中临时数据和编辑器历史仍需分别说明影响，不能凭目录名一概判为垃圾。
4. **简洁结果**：每组输出经过校验的 JSON，包含各容器的具体目录/文件、物理与容器内路径、实际占用、分类、用途和处理条件。没有条目时说明原因；不设置条目数或说明字数上限。格式无效或遗漏容器时，将具体校验错误反馈给模型，在原上下文中修正，保留已查询证据；发布前还会批量读取同一版本的记录，核对物理路径、容器映射和实际分配字节数；拼错路径、归属混淆或占用不符同样反馈修正，无法核实的项目移入备注。只有校验通过才发布结果。存储或模型请求失败时停止，已完成组的结果保留在时间线中。
5. **归并报告**：程序将各组结果按四类、固定文件用途归并，同用途按占用降序，只生成一份 Markdown 表格报告，不再调用模型扩写。数据集、模型权重、实验产物、环境、包缓存、编译缓存、日志、临时文件和编辑器历史分别聚合。相同物理路径只列一次，保留引用它的各容器；组间分类冲突转为“存在争议”。共享路径采用后一次观察的占用。每类显示已知实际占用总计，同类父子路径仅计入已知占用的上级目录；容量未知且未被已知上级覆盖的条目标明数量，不当作零占用。不同类别可能存在父子重叠，四类总计不可直接相加，也不代表可回收空间。

报告覆盖容器空间用途及有实际清理价值的项目；记录信息在末尾集中标注。工具只读元数据，不执行清理，不验证进程依赖或内容重复。第四类表示存放位置需要调整，不表示可以删除。

## HTTP 接口

所有接口要求管理员会话。变更请求携带 `X-CSRF-Token` 和 JSON 请求体，令牌从 `GET /api/session` 获取；分析会话仅创建者可访问。

| 接口 | 请求与结果 |
|---|---|
| `GET /api/agent/settings` | 配置及版本，Key 仅返回 `has_api_key` |
| `PUT /api/agent/settings` | `{revision, value}`；value 包含 `protocol`、`endpoint`、`model`、`api_key`、`clear_api_key`、`timeout_seconds`、`reasoning_summary` |
| `GET /api/agent/sessions` | 当前账号最近 50 个分析 |
| `POST /api/agent/reports` | `{snapshot_id, revision}`；从所选已完成扫描生成总报告，返回 202；版本不匹配返回 409 |
| `POST /api/agent/sessions` | `{message}`；新建分析，返回 202 |
| `GET /api/agent/sessions/:id?after=0` | 状态、扫描进度及消息；最多 200 条，返回 `next_after`、`has_more` |
| `GET /api/agent/sessions/:id/events?after=0` | SSE 实时事件；`session` 事件携带与查询接口相同的结构，支持 `Last-Event-ID` 续传 |
| `POST /api/agent/sessions/:id/messages` | `{message}`；继续提问 |
| `POST /api/agent/sessions/:id/cancel` | `{}`；停止模型请求及本轮扫描 |

模型接口必须支持 SSE 流式输出。Chat Completions 使用 `stream:true` 和 `stream_options.include_usage:true`；Responses 使用 `stream:true`、`store:false`。非流式 JSON、缺少结束事件、输出截断和无效工具调用均明确报错，不将部分输出保存为完整报告，不自动重新发起付费请求。协议参考 [Responses 流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events) 与 [Chat Completions 流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。

`reasoning_summary` 是可选布尔设置，默认关闭；开启后仅在 Responses 请求中传递 `reasoning:{summary:"auto"}`，需要所选模型支持。页面仅展示接口公开的思考摘要及模型面向用户的进度文字，不展示原始内部推理或加密内容。服务不支持摘要参数时报错，需在模型设置中关闭；不自动重试。

`protocol` 为 `completions` 或 `responses`，`endpoint` 支持基础地址或完整接口地址。保存空 Key 表示保留，`clear_api_key:true` 表示清除。

模型请求以 `project-alpha/0.1` 标识客户端，并携带 `x-opencode-session`，值为当前分析会话 ID；工具轮次与追问保持相同 ID，新分析使用新 ID。使用 OpenCode Go 或转发它的代理时，需保留该请求头，否则服务会返回 HTTP 400 `MissingSessionID`。接口协议须与所选模型匹配，参见 [OpenCode Go 接口说明](https://opencode.ai/docs/go/#endpoints)。

`POST /api/agent/sessions` 是另行建立全盘基线的自定义分析入口：先扫描宿主机 `/`，启用 Docker 自动发现时也扫描 Docker 资源。Web 一键报告使用 `/api/agent/reports`，不会为每份报告另建全盘扫描。两个入口共用会话、追问、取消与查询接口。

## 对话、上下文与用量

对话时间线按顺序显示初始报告任务、追问、预载证据、每次模型请求、公开输出/思考摘要及工具执行。工具卡片显示完整参数、执行状态、耗时和返回证据；模型正在生成的工具参数标为“准备调用”，不算作已执行。视图在靠近末尾时跟随新内容，向上阅读时保持位置，也可“跳到最新”。

每次模型请求发送前保存上下文快照，可逐项展开系统指令、用户/助手消息、本轮工具调用和返回结果，以及可用工具定义。上下文按照实际发送顺序展示；内部推理状态用明确的占位说明代替。追问重取当前扫描概览，只带入最近 24 条用户/助手消息；此前工具证据仍保留在时间线中，但不会自动全部进入下一轮上下文。同组工具结果会逐次加入后续请求，组间不携带历史工具输出或其他组的分析；完整报告由已校验的分组结果归并。

顶部展示最近一次请求的上下文项数、序列化字节数、输入/输出 token，以及会话累计 token 和已统计的请求数。用量来自服务返回的 `usage`；累计输入按每次请求相加，因此会包含重复发送的历史上下文，不能当作当前上下文窗口占用。缓存 token 属于输入，推理 token 属于输出，不重复累加。服务未返回、请求仍在执行或中途取消时，用量标为未提供/等待统计，不推算成零；上下文字节数不等于 token 数，也不据此猜测模型窗口占用比例。

公开分片约每 150 ms 合并保存为追加事件；浏览器通过 SSE 每约 250 ms 获取已保存消息和扫描进度。连接最多持续 25 秒，随后按消息游标恢复；关闭窗口、刷新页面和重连都不会重复事件或停止后台分析。查询每页最多 200 条，内容约 1 MiB（单个事件完整返回），需要遵循 `has_more` 分页。

消息角色包括 `user`、`status`、预载 `tool_result`、`model_request`、`model_delta`、`model_response`、`tool_start`、`tool_end`、`note`、分组结果 `group_report` 和最终 `assistant`。模型事件通过 `request_id` 关联，工具执行通过 `call_id` 关联；分片与最终回复使用不同角色，追问只读取完成的用户/助手消息。失败、停止或重启后，已经保存的公开内容仍可回看，并标明未完成。

## 模型工具

| 工具 | 参数 | 用途 |
|---|---|---|
| `get_overview` | `{}` | 摘要、主机名、已扫描根目录、Docker 发现状态、设备对账及完整性 |
| `list_containers` | `query, sort_by, offset, limit` | 容器排行；支持 `exclusive`、`writable`、`docker_logical` 排序 |
| `list_owners` | `offset, limit` | 用户去重用量与跨用户共享 |
| `get_container` | `container` | 按完整 ID 或精确名称查询存储来源 |
| `get_directory` | `path, offset, limit` | 查询已保存的目录明细 |
| `scan_directory` | `path, depth` | 在原记录上增量探索；执行端读取最新版本，depth 为 1–32 层 |

分组只限定最终结果负责的容器，不屏蔽工具；可查询其他容器、完整概览及用户排行来核对关联。

分页最多 50 项。探索路径须为当前记录中已有的物理目录绝对路径，未知路径需要从已记录的父目录逐层探索；排除平台数据、虚拟文件系统及 Docker merged 视图。增量探索复用基线的后端和排除设置，使用当前保存的扫描模式；与 Web 的目录探索共用 worker、锁、版本校验和发布流程。结果直接更新原记录，Web 的快照、轮询和 SSE 可读取同一版本。所有查询结果携带 `revision` 和 `updated_at`。Agent 在每次扫描执行前读取最新版本并提交探索，同一模型回复中的多个扫描依次执行，避免自身发布导致后续调用版本过期。存储层仍校验版本；外部并发更新造成的冲突仍明确返回，不绕过校验。

## 执行与数据

同一服务同时运行一个分析，扫描共用单 worker。单次分析最长 2 小时，单次目录细查最多 10 分钟；工具调用没有次数预算，模型自主结束分析或由用户停止。服务关闭会取消分析，异常重启后标为中断；已保存的消息和结果保留。

目录细查返回最大 40 个文件、扩展名汇总及 90/180 天 mtime 分布，只读取元数据。mtime 和 ctime 不能证明文件最近被读取或可以删除；文件统计以 `analysis_observed_at` 标记观察时间；每次探索使相交目录的旧文件统计失效，完成后保存本次统计。全盘与局部观察不能相加。统计定义见 [存储统计口径](accounting.md)。

模型服务会收到问题、路径和统计结果。API Key 保存在权限为 `0600` 的 SQLite 文件中，不额外加密，完整备份包含凭据。Key 不回传浏览器、不写入审计或扫描快照；历史消息不保存原始 reasoning items、内部推理正文或加密推理内容；Responses 的加密推理项只在同一轮分析的内存中回传。
