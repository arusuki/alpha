# 存储统计口径

扫描按 `st_blocks × 512` 统计实际分配空间，通过 inode 去重，不跟随符号链接。Docker `SizeRw` 是独立的逻辑大小，不加进实际占用。目录明细预算只影响保留的节点，折叠内容仍会遍历并计入总量。

## 空间归属

- **容器独占**：仅被一个容器引用的实际空间，包含可写层、挂载和日志。
- **容器共享**：被多个容器引用的空间，全机只计一次；各容器的共享引用不能跨行相加。
- **用户用量**：同一用户的多个容器共享时只计一次；跨用户共享单列。多个待归属容器不视为同一用户。
- **Host**：已扫描且未被容器引用的空间。“全部已扫描目录”包含容器数据，与 Host 范围不可相加。
- **未知／部分统计**：路径无法定位、被排除或读取失败时保留状态，未知部分不按零估计。

归属由资源路径及硬链接、目录别名的引用关系确定。父子挂载的交集属于共享空间；折叠引用可能导致归属不完整。容器所属用户不代表文件创建者。

普通目录明细折叠不影响 Host 归属：内容仍已遍历并计入容量。折叠的硬链接按保留的来源目录和目标范围核实；两端及其引用链均属于 Host 时，可以作为 Host 报告证据。保留的引用指向折叠文件时，可由已扫描且保留折叠计数的父目录提供证据。涉及容器引用（包括零字节）、Docker 数据目录、读取失败或无法定位的目标时，相关路径仍不能作为完整 Host 条目。`host_only_blocker` 返回阻止判定的路径、原因代码和说明；权限不足不应解释成容器共享。硬链接的去重占用不代表删除单个路径后可释放的空间。

整盘对账：`尚未解释 = 文件系统已用 − 已扫描实际占用`。差额可能包含未扫描目录、读取失败、文件系统元数据及已删除但仍打开的文件；负差额保留为“扫描超出”。扫描是遍历期间的观察值，差额不代表可回收空间。

## 目录明细

点击目录进入下一层，点击灰色待分析区块启动局部扫描。目录面积包含自身和折叠内容；“其他”区块展开较小项。引用路径显示零面积，未知项保留状态。

目录扫描只遍历目标物理路径。`depth` 在 API 中默认 1，允许 1–32；网页默认 3，可在“单次探索深度”选择。深度限制新增展示明细，不限制递归字节统计；提高深度可在同一次遍历中保留多层明细，避免逐层下钻反复测量。再次扫描父目录时保留已展开的后代路径，让新测量逐项替换历史统计，避免折叠后的累计字节与旧明细重复相加。常规明细预算为 10 万节点，已有明细保留后整条记录仍最多 25 万节点。扫描中，已测量子项逐步替换历史占用；完成后修正增长、缩小和删除。外部引用无法核对或读取失败时保留已有占用并标为未知。

变化节点、祖先汇总和版本在同一 SQLite 事务提交，通过 SSE 推送。取消或中断保留已提交的明细；未涉及的目录保留原观察值。`updated_at` 和 `scan.last_incremental` 标记更新时间与扫描范围。
